# Комиссия по проектированию `AgentAllocateSubtasks`

← [[Agent Index]] · блокирует §7.3 и §7.4 аудита · следующая задача по
умолчанию по HANDOFF.md §5.7

## 0. Регламент

Агент проектируется не единоличным решением, а согласованием пяти
позиций. Каждая позиция имеет **право вето в своей области**: решение
считается согласованным только если ни одна позиция не заявила вето по
итоговому объёму. Разногласия разрешаются явно (§3), каждое проектное
решение получает ссылку на источник (§5). Пункты, которые комиссия не
вправе решить сама (они меняют текст диссертации или онтологическое
ядро), выносятся автору на ратификацию (§6) и до ответа не реализуются.

Основание регламента — методология проекта HANDOFF.md §5.1: «Не
изобретать формулы/алгоритмы. Каждое правило в коде должно быть дословно
взято из `part2.tex` или уже существующего текста KB — не «правдоподобно
достроено»». Комиссия существует именно для того, чтобы это требование
проверялось независимыми позициями, а не самим исполнителем.

## 2. Позиции комиссии

### 2.1. Формализатор — соответствие главе 2

**Установлено.** Статус шести слагаемых `match(σ,s∣C)` на текущую
редакцию гл. 2 **изменился** по сравнению с тем, что записано в
`Implementation Backlog.md:213` («из 6 слагаемых вычислимо только
`trust`»):

| Слагаемое | Статус в гл. 2 | Вычислимо из KB |
|---|---|---|
| `sim_T` | **формализовано полностью** — `eq:sim_type`, мера Ву—Палмера по таксономии `Ω` | **да** (таксономия `concept_task_type` есть) |
| `sim_In` | не формализовано | нет |
| `sim_Out` | не формализовано | нет |
| `ctx_compat` | формализована только **структура** (`eq:context_compatibility`: взвешенная сумма пяти `sim_k`); сами `sim_k` — свободные функции | нет |
| `qos` | не формализовано | нет |
| `trust` | формализовано: `Σ_k λ_k t_k` | да (`AgentAggregateTrust`) |

Текст прямо отмечает, что `eq:sim_type` «устраняет одну свободную
функцию». Backlog этого не учитывает — он написан до ревизии главы.

**Вето.** Формализатор налагает вето на любую реализацию, вычисляющую
`match` как взвешенную сумму: четыре из шести слагаемых в тексте не
определены, и подстановка любых значений (нулей, единиц, «разумных»
эвристик) под именем `match` есть ровно то изобретение формулы, которое
запрещено §5.1. Число, похожее на `match`, но им не являющееся, хуже
отсутствия числа: оно непроверяемо и попадает в провенанс как факт.

**Не возражает** против: вычисления `sim_T` как самостоятельной величины
(она определена дословно); проверки `match ≥ θ` над значением,
**переданным вызывающей стороной**; шага 2.3 листинга (выбор `k(σ)`
наибольших) — он задан дословно и снабжён утверждением об оптимальности.

### 2.2. Онтолог — состояние KB

**Установлено — расхождение внутри KB.** Предикат `assign(σ,s)`
записан в базе **в трёх несовпадающих редакциях**:

| Место | Редакция |
|---|---|
| `concepts/capabilities.scs:308` | `match ≥ θ ∧ valid ∧ permit ∧ available` — **актуальная** |
| `axioms/axioms_constraints.scs:259` | `match ≥ θ ∧ valid` — устаревшая |
| `rules/rules_allocation.scs:41` | `match ≥ θ ∧ valid` — устаревшая |
| `concepts/tasks.scs:261` | `match ≥ θ ∧ allow(q,P_k)` — третий вариант; `allow` не определён нигде |

Правка от §7.3 аудита затронула только `capabilities.scs`; три остальных
текста остались в прежней редакции. Агент, операционализирующий
`rule_assignment_admissibility` буквально, реализовал бы устаревшую
двухконъюнктную формулу.

**Установлено — вычислимость конъюнктов:**

- `available(s,C)` — **вычислим**: `nrel_entry_status` записи реестра
  равен `concept_registry_status_active`. Опора не изобретена:
  `affirmation_registry_required_for_assignment` прямо говорит, что
  `nrel_assigned_to(σ,s)` допустимо только для участника с активной
  записью.
- `permit(view(C,s),s,C)` — **вычислим как графовый факт**: политика
  записи (`nrel_entry_policy`) связана с участником отношением
  `nrel_permits` (`relations_control.scs:29`).
- `valid(C,L_s)` — **невычислим**: экземпляры `L_s` существуют, но
  заданы естественно-языковыми ссылками («Требует GPU ≥ 6 ГБ VRAM»,
  `examples/example_capabilities.scs`); предиката сравнения контекста с
  ограничением ни текст, ни KB не задают.
- `match ≥ θ` — см. §2.1; значение не вычислимо внутри агента.

**Установлено — недостающие носители.** Grep по всему
`ostis_kb_user_ecosystem/` (§5.2 методологии):
- ни одно `nrel_*` не несёт числового значения `match` — 0 совпадений;
- классы `concept_route_*` объявлены, но **ни разу не привязаны** ни к
  запросу, ни к подзадаче — 0 совпадений вне `concepts/tasks.scs`;
  носителя кратности `k(σ)` в KB нет вовсе.

**Есть готовая цель реификации:** `concept_process_allocation` с шестью
ролями (`rrel_subtask`, `rrel_assignee`, `rrel_context`,
`rrel_assignment_time`, `rrel_required_confidence`, `rrel_priority`) —
прецедент в трёх сценариях; `concept_state_assignment
=> nrel_activates_process: concept_process_allocation`
(`mediation_lifecycle.scs:486`) уже связывает это с жизненным циклом.

**Вето.** На реализацию агента поверх устаревшей редакции
`rule_assignment_admissibility` без предварительной актуализации KB.
Агент, расходящийся с собственной онтологией, ломает основание §7.3.

### 2.3. Архитектор агентного слоя — соответствие модулю

**Установлено.** Соглашения модуля, соблюдаемые всеми 27 агентами:
`ScActionInitiatedAgent`; аргументы через `GetArguments<N>` (в проекте
уже используются арности 2–7, поэтому 5–6 аргументов не выходит за
практику); `IsElement` по каждому аргументу; результат — float-link
`1.0`/`0.0` под `resultLevel`; `FormResult`; **ни один агент не
вызывает действие другого агента** — композиция только внешняя
(`test_integration_request_pipeline.cpp`).

**Прецедент принятия посылки от вызывающей стороны** установлен трижды:
`AgentHandleNoAdmissibleAssignment` (посылка «нет допустимого
исполнителя»), `AgentExcludeFromCoalition` (`failed`),
`AgentReassignOnResourceExhaustion` (`resource_exhausted`). Приём
легитимен и документирован; распространение его на значение `match`
однородно с уже принятым.

**Не возражает** против расширения `AllocationKeynodes` (файл уже
существует ровно под `rules_allocation.scs`) и регистрации в
`TrustModule` — реорганизация модуля (§7.6) отложена сознательно.

**Условие.** Агент обязан отказывать (`FinishWithError`), а не
домысливать, при отсутствии любого из обязательных входов. Никаких
значений по умолчанию для `θ` и `k(σ)` внутри кода — иначе параметр
настройки главы 2 окажется зашитым в C++ и выпадет из воспроизводимости.

### 2.4. Верификатор — проверяемость

**Установлено — оракул существует:** `tests/tests_capability_match.scs`
(TM1–TM4) и числовой пример гл. 2 (`tbl:example_match`, 4 пары, порог
отсекает `s_4`).

**Установлено — оракул рассогласован с текстом.** TM1 задаёт веса
`w = (0,30; 0,10; 0,10; 0,20; 0,15; 0,15)` и `θ = 0,6`. Глава 2
(`part2.tex:2189`, и правило фиксации в разделе верификации) задаёт
`w_R = 0,25`, остальные пять — по `0,15`, `θ = 0,70`. Расхождение не
косметическое: при `θ = 0,6` участник `s_4` с `match = 0,608` прошёл бы
порог, тогда как текст прямо пишет, что `s_4` отсекается. Оба
утверждения одновременно истинными быть не могут.

**Вето.** На использование TM1 как эталона до устранения расхождения.
Тест, противоречащий главе, при защите работает против работы.

**Требование.** Полный цикл §5.3 после реализации: `sc-builder --clear`
с сверкой счётчика (базовая линия — 34741), `ctest` весь зелёный,
чек-сумма `ostis_ps_user_ecosystem/repo/` идентична до/после.

### 2.5. Методолог — защитимость

**Риск, который комиссия обязана назвать.** Агент под именем
«распределитель подзадач», не вычисляющий `match`, может быть воспринят
как фасад. Позиция методолога: это приемлемо и защитимо **при одном
условии** — граница «вычисляем / принимаем как данность» названа явно в
коде, в карточке агента и в аудите, с указанием причины (слагаемое не
формализовано в тексте). Ровно так уже сделано в трёх агентах, и именно
это отличает честную частичную реализацию от имитации.

**Содержательный вклад агента при этом не нулевой:** три из четырёх
конъюнктов допустимости становятся машинно проверяемыми впервые в
проекте; шаг 2.3 листинга реализуется дословно и опирается на доказанное
утверждение об оптимальности; акт назначения впервые порождается
агентом, а не лежит фикстурой в сценарии. Это снимает блокировку §7.3
(`AgentDispatchReadySubtask` получает того, кто установил допустимость)
именно так, как предсказывал аудит.

**Вето.** На любое умолчание, подставляемое молча: отсутствие записи
реестра не должно означать «доступен», отсутствие политики не должно
означать «разрешено». Отсутствие факта — это отсутствие факта, и агент
обязан различать «условие не выполнено» и «условие не проверялось».

## 3. Разногласия и их разрешение

**Р-1. Вычислять ли `match` внутри агента?**
Архитектор: приём «посылка от вызывающей стороны» уже узаконен, можно
принять `match` как данность. Формализатор: да, но тогда агент
называется распределителем, не вычисляя главного.
*Разрешено:* агент **не вычисляет** `match` (вето §2.1 в силе) и
принимает его как факт KB. Вычисление `sim_T` по `eq:sim_type` —
единственное слагаемое, доступное без изобретения — выделяется в
**отдельную задачу** (`AgentComputeSimType`), поскольку это
самостоятельный вклад (закрывает одну из шести свободных функций) и
смешивать его с распределением значит скрыть его в чужом агенте.
Рекомендовано следующим пунктом бэклога после настоящего.

**Р-2. Что делать с четвёртым конъюнктом `valid(C,L_s)`?**
Онтолог: невычислим. Методолог: молчаливо считать выполненным нельзя.
*Разрешено:* агент проверяет три конъюнкта из четырёх и **отдельно
сообщает**, что `valid` не проверялся, а не подразумевает его истинным.
Технически: `valid` принимается как данность от вызывающей стороны тем
же приёмом, что и `match`, и это фиксируется в карточке и в аудите как
именованный открытый хвост.

**Р-3. Откуда берётся `k(σ)`?**
Онтолог: носителя в KB нет. Архитектор: нельзя зашивать `k=1` в код.
*Разрешено:* `k(σ)` — обязательный аргумент действия. Введение
отношения маршрута в KB — вопрос автору (В-3), до ответа не делается.

**Р-4. Какую редакцию `assign` реализовать?**
Онтолог требует актуализации трёх устаревших текстов; это правка
онтологического ядра, включая `axioms/`.
*Разрешено:* реализуется **актуальная четырёхконъюнктная** редакция
(`capabilities.scs`, совпадает с `eq:assignment_admissibility`).
Актуализация трёх расходящихся текстов выносится автору (В-2), так как
затрагивает `axioms_constraints.scs` — файл, на который опираются другие
агенты.

## 4. Согласованный объём агента

Вето снято всеми пятью позициями при следующем объёме.

**Агент выполняет:**

| # | Действие | Источник |
|---|---|---|
| 1 | Перебор кандидатов `s ∈ S` — участников с профилем возможностей | `eq:admissible_executors` |
| 2 | `available(s,C)`: активная запись реестра | `affirmation_registry_required_for_assignment` |
| 3 | `permit(·)`: политика записи разрешает участника (`nrel_permits`) | `eq:assignment_admissibility`, `relations_control.scs:29` |
| 4 | `match(σ,s) ≥ θ` над **переданным** значением и **переданным** `θ` | `eq:assignment_admissibility` |
| 5 | Построение `S_{σ,C}`; при `∣S_{σ,C}∣ < k(σ)` — отказ без домысливания | `eq:admissible_executors`, `lst:greedy` шаг 2.2 |
| 6 | Выбор `k(σ)` кандидатов с наибольшим `match` | `lst:greedy` шаг 2.3 + `stmt:greedy_optimal` |
| 7 | `nrel_assigned_to(σ,s)` для каждого выбранного | `eq:assignment_map` |
| 8 | Реификация акта `concept_process_allocation` с шестью ролями | `role_relations.scs:105–131`, `rule_assignment_admissibility` (консеквент) |
| 9 | Провенанс акта назначения | `lst:greedy` шаг 2.4 |

**Агент не выполняет (и это названо явно):**

| Не выполняется | Причина |
|---|---|
| Вычисление `match` | 4 из 6 слагаемых не формализованы (вето §2.1) |
| Проверка `valid(C,L_s)` | предикат не задан ни текстом, ни KB (Р-2) |
| Повторная декомпозиция при `S_{σ,C}=∅` (шаг 2.2а) | `rule_apply_decomposition_pattern` не реализовано; путь уже распознаёт `AgentHandleNoAdmissibleAssignment` |
| Переназначение по `b_q` (шаг 2.5) | область `AgentReassignSubtask` (§7.5) |
| Выбор маршрута и вычисление `k(σ)` | носителя в KB нет (Р-3, В-3) |
| Связывающее ограничение `consistent(C,χ)` | при непустом множестве таких условий гарантий у жадной процедуры нет (`part2.tex:1878`); задача межподзадачная, агент работает над одной `σ` |

**Аргументы действия `action_allocate_subtasks` (арность 6):**
`σ` (подзадача) · `θ` (порог, link) · `k` (кратность, link) ·
`C` (контекст) · `assignment_time` (метка времени, link) · `resultLevel`.

Шестой аргумент добавлен при исполнении: `prov_template_assignment`
(`axioms/axioms_provenance.scs`) требует у акта назначения роль
`rrel_assignment_time`, а источника времени в проекте нет ни у одного
агента (§7.3 аудита прямо называет это открытым пунктом). Синтезировать
метку внутри агента значило бы ввести в KB факт, не выводимый из
модели, поэтому она передаётся вызывающей стороной.
Результат: `1.0` — назначение построено; `0.0` — допустимых исполнителей
меньше `k(σ)` (сигнал вызывающей стороне на путь
`AgentHandleNoAdmissibleAssignment`).

## 5. Обоснование по каждому решению

| Решение | Обоснование | Источник |
|---|---|---|
| Четыре конъюнкта, не два | Актуальная редакция гл. 2; двухконъюнктные тексты KB отстали от ревизии | `eq:assignment_admissibility`; `capabilities.scs:308` |
| `available` через статус реестра | Единственная запись в KB, дословно связывающая допустимость назначения с состоянием участника | `competency_registry.scs:188` |
| `permit` через `nrel_permits` | Отношение существует с доменами «политика → участник»; изобретения нет | `relations_control.scs:29` |
| `θ` — аргумент, не константа | `θ` объявлен настраиваемым параметром, фиксируемым до оценочного прогона; зашивание в код лишило бы работу воспроизводимости | `part2.tex:2405` |
| Выбор `k` наибольших, а не одного | `χ` отображает в подмножества, `∣χ(σ)∣=k(σ)`; `nrel_assigned_to` не объявлено функциональным именно ради этого | `eq:assignment_map`, `part2.tex:1719` |
| Жадный выбор считается точным, а не приближённым | При сепарабельных ограничениях покомпонентный максимум совпадает с максимумом суммы | `stmt:greedy_optimal` |
| Отказ при `∣S_{σ,C}∣ < k(σ)` | «Посредник должен возвратить отказ… но не должен скрывать отсутствие компетенции под видом успешной обработки» | `part2.tex:1755` |
| Реификация акта назначения | Требуется и правилом KB (консеквент), и провенансной аксиомой | `rules_allocation.scs:44`, `axioms_provenance.scs:87` |
| `match` принимается как данность | Приём уже узаконен тремя агентами; альтернатива — изобрести 4 слагаемых | `AgentHandleNoAdmissibleAssignment` и др. |
