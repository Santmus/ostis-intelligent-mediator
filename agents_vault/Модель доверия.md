# Модель доверия T(s, τ)

Источник: `ostis_kb_user_ecosystem/concepts/trust.scs`.

```
T(s, τ) = ⟨t_rel(s,τ), t_acc(s,τ), t_sec(s,τ), t_tr(s,τ)⟩
trust(s, τ, h) = λ_rel·t_rel + λ_acc·t_acc + λ_sec·t_sec + λ_tr·t_tr,  Σλ = 1
```

- `s` — интеллектуальная система сообщества.
- `τ` — контекст/тип задачи.
- `h` — история взаимодействий, по которой инкрементально обновляются компоненты.
- Каждая компонента ∈ [0, 1] *по замыслу онтологии*; ни один из агентов
  это диапазон программно не проверяет (см. Limitations в заметках
  агентов).

## Компоненты

| Символ | Заметка | Обновляется |
|---|---|---|
| t_rel | [[AgentUpdateTrustReliability]] | индикатором успешности взаимодействия ν_rel |
| t_acc | [[AgentUpdateTrustAccuracy]] | достигнутой точностью результата q_res |
| t_sec | [[AgentUpdateTrustSecurity]] | индикатором отсутствия инцидента ν_sec |
| t_tr | [[AgentUpdateTrustTransparency]] | индикатором предоставления обоснования ν_tr |
| trust | [[AgentAggregateTrust]] | взвешенной суммой четырёх компонент выше |

## Хранение в sc-памяти

Компонента представлена узлом-контейнером `trust_level` (экземпляр
`concept_trust_level`), к которому положительной постоянной дугой
(`ConstPermPosArc`) привязана числовая sc-ссылка со значением:

```
concept_trust_level -> trust_level;;
trust_level -> value_link;;      // value_link = sc-ссылка, content = "0.838000"
```

Значение хранится как **текстовая** строка (не сырые байты float) —
см. пояснение в `common/float_link_io.hpp`, вызванное несовместимостью
путей сериализации `SetLinkContent`/`GetLinkContent` для чисел в
sc-machine. Один и тот же `concept_trust_level` используется как общий
контейнер для любой из компонент — какая именно компонента у
конкретного `trust_level` хранится, определяется по контексту
(идентификатору узла), а не типом sc-элемента: в коде нет отдельного
класса на каждую компоненту.

## Назначение в системе

`trust(s, τ, h)` используется функцией подбора исполнителя `match(σ, s)`
при распределении подзадач между интеллектуальными системами
сообщества — модель самонастраивается: систематические успехи растят
доверие, систематические отказы/инциденты его снижают, что
автоматически уменьшает вероятность назначения подзадач ненадёжной
системе без внешнего вмешательства.
