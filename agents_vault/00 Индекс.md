# Онтологические описания агентов ostis_ps_user_ecosystem

Восемь sc-агентов модуля `TrustModule` ([[ostis_ps_user_ecosystem]]): пять
реализуют правила обновления вектора доверия π_tr, один — вычислимую
часть метрик полноты провенанса, один — детектирование аномальной
частоты запросов, один — разрешение конфликта результатов по
взвешенному доверию. Код: `ostis_ps_user_ecosystem/src/agent/`.
Онтология правил: `ostis_kb_user_ecosystem/rules/`.

| Агент | Действие | Обновляет | Тип |
|---|---|---|---|
| [[AgentUpdateTrustReliability]] | `action_update_trust_reliability` | t_rel | сглаживание (EMA) |
| [[AgentUpdateTrustAccuracy]] | `action_update_trust_accuracy` | t_acc | сглаживание (EMA) |
| [[AgentUpdateTrustSecurity]] | `action_update_trust_security` | t_sec | сглаживание (EMA) |

| [[AgentAggregateTrust]] | `action_aggregate_trust` | trust(s,τ,h) | взвешенная агрегация |
| [[AgentComputePiMetric]] | `action_compute_pi_metric` | π_proc / π_dec / π_data | доля с провенансом |

| [[AgentResolveByTrustWeighted]] | `action_resolve_by_trust_weighted` | integrated_result | argmax по trust |

## Как читать эти заметки

Каждая заметка агента — по фиксированному шаблону: Идентификация →
Назначение → Компетенция → Вход → Выход → Связи → Поведение →
Безопасность → Метрики → Тесты. Раздел «Безопасность» и часть
«Limitations» в «Компетенции» получены разбором реального кода
(`m_context.IsElement(...)` — единственная проверка аргументов), а не
предположениями — это осознанные, проверенные ограничения текущей
реализации, а не общие фразы.

## Сквозные зависимости

Все восемь агентов используют:
- `common/float_link_io.hpp` — общий `WriteFloatLinkContent` (и
  `ReadFloatLinkContent` — все, кроме [[AgentComputePiMetric]], которому
  для подсчёта достаточно факта существования связи).
- `keynodes/trust_keynodes.hpp` (`TrustKeynodes`) / `keynodes/provenance_keynodes.hpp`
  (`ProvenanceKeynodes`) / `keynodes/security_keynodes.hpp`
  (`SecurityKeynodes`) / `keynodes/integration_keynodes.hpp`
  (`IntegrationKeynodes`) — ключевые sc-элементы и классы действий.
- Базовый класс `ScActionInitiatedAgent` (sc-machine) — реакция на
  событие `ScEventAfterGenerateOutgoingArc` с элементом подписки
  `action_initiated`.
- Один и тот же C++ модуль `TrustModule` — sc-machine допускает только
  один модуль (`SC_MODULE_REGISTER`) на разделяемую библиотеку, поэтому
  [[AgentComputePiMetric]], [[AgentDetectAnomalousRequestRate]] и
  [[AgentResolveByTrustWeighted]] зарегистрированы там же, несмотря на
  название.

[[AgentAggregateTrust]] зависит от результатов остальных трёх EMA-агентов
(не от [[AgentComputePiMetric]]/[[AgentDetectAnomalousRequestRate]]) —
читает их `value_link`, но не инициирует их сама (порядок вызова —
забота внешнего оркестратора). [[AgentResolveByTrustWeighted]] в свою
очередь читает тот же `trust_level`, что наполняет
[[AgentAggregateTrust]] — единственная связь по данным между
«семействами» агентов проекта.
